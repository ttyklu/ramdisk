ZC706 NVMe RAM Disk (with hardware compression)

A hardware NVMe controller for the ZC706 that serves a namespace out of DDR3. No ARM firmware is involved: admin and I/O commands are handled entirely in the FPGA fabric. Hardware gzip (zlib) compression for ZFS runs through vendor commands: a streaming two-phase write (Compress-to-Staging, then Commit) and a single-phase Decompress-Read, plus a subset of the draft SNIA FFE-Send / FFE-Receive commands. The namespace is RAW by default. Interface: docs/compression_spec.md.

Status: the self-checking testbench passes in both Vivado xsim 2026.1 and Verilator 5.032, for 128 KB records (20/20 random seeds) and the optional 1 MB build. The deflate / inflate engines also pass 494 unit checks against Python's zlib. Out-of-context place and route on the ZC706 part (xc7z045ffg900-2) meets timing at 125 MHz for both builds (WNS +0.15 ns at 128 KB, +0.30 ns at 1 MB).

On hardware (ZC706, fpga/zc706/, DDR3-800): the board enumerates under the Linux 7.0 nvme driver as nvme1n1 (960 MiB, 4 KB blocks) and trains at Gen2 x4. The whole namespace reads back byte-for-byte with no PCIe errors (scripts/pcie_check.py), and the two-phase compressed write, Decompress-Read and their error cases pass 349 of 349 checks (scripts/staging_hwtest.py). See Testing on the board.

The testbench brings the controller up the way the Linux nvme driver does (CAP/VS reads, admin queue, CC.EN, Identify, Set Features, create I/O queues), then runs error cases and about 90 reads/writes with random sizes, PRP1 offsets, PRP2 and chained PRP lists on two I/O queues. Every read is compared against a disk model. Completions to the controller's reads are split at 64 B boundaries and interleaved across tags; the TX interface and the DDR model apply random backpressure.

Testing on the board

Build and boot: cd fpga/zc706 && vivado -mode batch -source build.tcl, then ./boot/make_boot.sh and copy boot/work/BOOT.bin to the SD card as BOOT.BIN. The board boots from SD. The SODIMM (MT8JTF12864HZ-1G6G1) only calibrates at DDR3-800, which is what the build uses.

Check that the host sees it:

lspci -nn -d 10ee:                              # Non-Volatile memory controller [10ee:7024]
cat /sys/bus/pci/devices/0000:08:00.0/current_link_{speed,width}   # 5.0 GT/s PCIe, 4
lsblk -o NAME,SIZE,MODEL | grep ZC706           # nvme1n1  960M ZC706 NVMe RAM Disk

If the controller does not come up, reset the function and rebind it:

echo 1 | sudo tee /sys/bus/pci/devices/0000:08:00.0/reset
echo 0000:08:00.0 | sudo tee /sys/bus/pci/drivers/nvme/bind

The scripts need root, and sudo needs a terminal to ask for the password (it will not run from a ! command in Claude Code). Run them in a normal terminal.

PCIe core settings

pcie_7x settings the RTL assumes (used by fpga/zc706/gen_ip.tcl):

  • Gen2 (5.0 GT/s) x4, 128-bit AXI-Stream interface, 125 MHz
  • BAR0: 64-bit memory BAR, 16 KB, not prefetchable; no other BARs
  • Class code 0x010802 (mass storage / NVM / NVMe)
  • MSI-X capability: table size 5, table in BAR0 at offset 0x2000, PBA in BAR0 at 0x3000; MSI off
  • Vendor/device IDs of your choice (Identify reports VID/SSVID 0x10EE)

Connect user_clk_out / user_reset_out to clk / rst, cfg_bus_number, cfg_device_number, cfg_function_number, cfg_interrupt_msixenable and cfg_interrupt_msixfm. The AXI4 master goes through an AXI clock converter and interconnect to the MIG DDR3 SODIMM controller.

Known limits and assumptions

  • Payload byte order of the 7-series AXI-Stream interface is assumed little-endian per DW. If register writes or data come out byte-swapped on hardware, set PAYLOAD_BSWAP = 1.
  • No SGLs, no Write Zeroes / Dataset Management, no Compare; ONCS = 0.
  • Get Log Page ignores the log page offset.
  • Only physically contiguous queues (CAP.CQR = 1).
  • A controller reset finishes the command in progress before CSTS.RDY clears.
  • One command at a time: performance is not tuned yet. A compress blocks other I/O while it runs.
  • Compression uses fixed Huffman codes only: text compresses to about 29% (zlib level 6: 12%). On the board the test's word-list text gives 33% (zlib level 6: 15%), and 128 KB of zeros gives 1280 bytes (zlib: 149). A dynamic-Huffman encoder is the next ratio step.
  • Compress-to-Staging (81h) and Decompress-Read (86h) use MPTR. The Linux nvme driver does not pass a metadata buffer on a namespace without metadata, so they can only be sent from a user-space driver (VFIO, SPDK) or a kernel module. FFE-Send / FFE-Receive work through the standard passthrough ioctls.
  • Two correctable Receiver Errors (physical layer) are logged at the upstream root port when the link retrains after a function reset, for example when the board moves between vfio-pci and nvme. None were seen during data transfers.
  • The internal datapath moves 8 bytes per cycle: about 1 GB/s each way at 125 MHz, below the ~1.6 GB/s the link can carry. Widening the DMA paths to 4 DWs would close the gap.
  • Engines run at about 65 MB/s (deflate) and 70 MB/s (inflate) at 125 MHz, below the 200-250 MB/s target; match finding and Huffman decoding are bit- / byte-serial.
  • Staging slots are freed by Commit, FFE-Receive, Commit with DISCARD or a controller reset; there is no timeout yet.
  • FFE subset: at most 8 descriptors in the first page of PRP1, one source and one function, object-level CU, no PI, no partial object, compaction or filter; parameter data a 128-byte multiple.
