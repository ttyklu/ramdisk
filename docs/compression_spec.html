Compression path: command interface (draft 1)

Implements the streaming two-phase write and single-phase read from ZC706 NVMe RAM Disk: Streaming Two-Phase Write and Read Path (Nov 13, 2026), plus a subset of the draft SNIA FFE-Send / FFE-Receive commands (Fixed Function Data Structure Model, FFE diagrams) for compress (82h) and decompress (83h).

  • Compression format: zlib stream (RFC 1950) around a raw deflate stream (RFC 1951). Stage 1 is LZ77 match finding (32 KB window), stage 2 is Huffman coding. The encoder emits fixed-Huffman blocks; the decoder accepts stored, fixed and dynamic blocks, so it reads any zlib stream (for example one written by ZFS's software gzip).
  • Checksum: ZFS Fletcher-4 (four 64-bit sums over 32-bit little-endian words) of the stored bytes, zero padded to a 4 KB multiple (ashift = 12). Adler-32 of the uncompressed data is also reported.
  • Standard Read / Write never compress: the namespace is RAW by default.

Opcode bits 1:0 follow the NVMe data-direction convention.

The device copies the record into a free slot, deflates it into the slot's output area, zero pads to 4 KB and computes Fletcher-4. If the zlib stream is larger than the threshold allows, the record is marked incompressible and the raw data (padded) is kept.

Parameter data = 64-byte descriptors, then inline data. Restrictions of this implementation: at most 8 descriptors (512 bytes), all in the first page of PRP1; one source; one function (82h or 83h) plus its FPD (FEh); CU size 0 (object level); no PI, no partial object, no compaction, no filter.

FFE-Receive returns the CRB, then the retained output (decompressed data for 83h, stored bytes for an 82h with no LBA destination), and frees the List ID's slot.

82h takes an inline source (the record). 83h takes an inline or LBA source (the zlib stream); with an LBA source its length is NLB blocks and the stream end marks CSIZE.

Using it from a host

  1. Enable compression: Set Features FID C0h, CDW11 = 1 (CEN = 1, RECSZ = 0 for 128 KB records). Get Features C0h returns NSLOT in bits 31:16 (128 on the 128 KB build). Standard Read / Write keep working in both modes; the namespace stays RAW until CEN is set.
  2. Two-phase write of one record:
    • 81h Compress-to-Staging with the record in PRP1/PRP2, CDW10 = LSIZE, CDW11 = threshold (0 = ZFS rule) and MPTR pointing at a 64-byte host buffer. CQE DW0 has the handle and INCOMP; the Result Record at MPTR has CSIZE, PSIZE, Fletcher-4 and Adler-32.
    • Allocate PSIZE / 4 KB blocks, then 84h Commit with that SLBA, NLB = PSIZE / 4 KB - 1 and the handle. Several records can be staged before any is committed (up to NSLOT), and they can be committed in any order. Commit with DISCARD (CDW13 bit 31) drops a record. A Commit with the wrong NLB is refused with Invalid Field and the record stays staged.
  3. Read a compressed record back with 86h Decompress-Read: SLBA, NLB, CSIZE and ULEN from the Result Record, and MPTR pointing at that same record (the device takes the expected Fletcher-4 from offset 10h), or CDW15 bit 0 (NOCHK) to skip the check. An incompressible record (INCOMP) is stored raw: read it with a plain Read.
  4. Set CEN = 0 again to go back to RAW. A controller reset (CC.EN 1 -> 0) also returns to RAW and frees every slot.

What works through the Linux nvme driver

The vendor commands can be sent with the standard passthrough ioctl (NVME_IOCTL_IO_CMD, as nvme io-passthru does), with two host-side limits, both measured on Linux 7.0 with the IOMMU in DMA-FQ mode (scripts/vs_passthru_check.py, 2026-11-26):

  • No metadata buffer. A passthrough command with a metadata buffer on a namespace without metadata fails with EINVAL in the kernel, so MPTR cannot be supplied. Without one the kernel leaves MPTR at 0.
  • 128 KB per transfer. nvme-pci caps max_hw_sectors_kb at the IOMMU's optimal mapping size, 128 KB, below the board's MDTS (256 KB). The other NVMe drive in the host has the same cap. Larger commands fail with EINVAL before they reach the board.

So with stock Linux and an IOMMU, a 128 KB ZFS record has no complete compress path: 81h needs MPTR and FFE-Send needs 256 B more than the host allows. Decompress of a 128 KB record works with 86h and NOCHK (FFE-Receive cannot return it: CRB + 128 KB is over the limit). For full 128 KB records drive the controller from user space through VFIO, as scripts/staging_hwtest.py does.

sudo python3 scripts/staging_hwtest.py              # finds the 10ee board; or pass 0000:08:00.0
sudo python3 scripts/staging_hwtest.py --keep-vfio  # leave it on vfio-pci afterwards

staging_hwtest.py moves the board to vfio-pci, which needs the board alone in its IOMMU group and IOMMU enabled (Intel VT-d / AMD-Vi). The script then sets up the admin queue and one I/O queue pair (64 entries, no interrupts) and maps 4 MiB of DMA memory at IOVA 0x1000_0000. At the end it disables compression, clears CC.EN and rebinds the board to nvme. It refuses to run if a namespace of the board is mounted, and writes only LBAs >= 200000. It checks:

  • 81h and 84h refused with Command Sequence Error while RAW
  • For zeros, text, runs and random records of 512 B, 4 KB, 13.5 KB, 64 KB and 128 KB:
    • the CQE handle and INCOMP, and the Result Record: VALID, LSIZE, PSIZE = CSIZE rounded up to 4 KB, Adler-32 and the ZFS 12.5% rule
    • after Commit, a plain Read of the extent: Fletcher-4 matches the record, Python's zlib.decompress of the stored stream gives back the record, the padding is zero (or the raw data for INCOMP), and the block after the extent is untouched
    • 86h Decompress-Read of the extent returns the record
  • Threshold percent on both sides of the boundary CSIZE x 100 <= LSIZE x T
  • 8 records staged at once (distinct handles), committed in reverse order, all verified
  • Errors:
    • bad LSIZE (0, not a 512 multiple, above the record size)
    • NLB too large, then the right NLB succeeds
    • freed handle, handle >= NSLOT, LBA range
    • DISCARD, then the handle is gone
    • Staging Full after exactly NSLOT staged records, and the slots free again after discards
    • wrong Fletcher-4 (C2h), NOCHK, ULEN short (C4h)
  • 128 KB stage + commit and Decompress-Read rates
